# Internationalisation (i18n)

## Languages

`en` (default), `si` (Sinhala), `ta` (Tamil). In code this is the enum `com.suwalink.entity.Language`
(`EN, SI, TA`); JSON and the database always use the lowercase code (`"en"`, `"si"`, `"ta"`).

- Each user has `preferred_language` (default `en`) and an optional `district`, set with
  `PUT /api/users/me/preferences` (`{"preferredLanguage":"si","district":"KANDY"}`) and returned by `GET /api/users/me`.
- Request locale: `Accept-Language` (`en`, `si`, `ta`; anything else falls back to `en`) via `AcceptHeaderLocaleResolver`.
- Message bundles: `backend/src/main/resources/i18n/messages.properties` (en), `messages_si.properties`,
  `messages_ta.properties`; `MessageSource` basename `i18n/messages`, UTF-8, no system-locale fallback.
  Every key must exist in all three files (enforced by `UserPreferencesTest`).

## API error codes

**This table is the frontend contract:** it lists every `code` the API returns, and each one has an
`error.<code in lowercase>` key in all three bundles. Adding, renaming or removing a code means updating
this table and the bundles in the same change.

API error `message` stays English. The frontend translates the stable `code`
(and `errors[].code` for field errors, which is the constraint annotation name, e.g. `NotBlank`, `Size`, `AssertTrue`).
Bundle keys are `error.<code in lowercase>`.

| code | typical status | meaning |
|---|---|---|
| VALIDATION_FAILED | 400 | bean validation or invalid request content (incl. a wrong, expired or invalidated password-reset code) |
| MALFORMED_REQUEST | 400 | unreadable body or unknown enum value (e.g. language `fr`) |
| INVALID_PARAMETER | 400 | bad path/query parameter |
| MISSING_PARAMETER | 400 | required query/form parameter or multipart part missing |
| NOT_FOUND | 404 | resource missing, or no such endpoint |
| METHOD_NOT_ALLOWED | 405 | HTTP method not supported on this endpoint (`Allow` header lists the supported ones) |
| UNSUPPORTED_MEDIA_TYPE | 415 | request `Content-Type` not accepted by this endpoint |
| ACCESS_DENIED | 403 | not allowed |
| UNAUTHENTICATED | 401 | bad credentials |
| DUPLICATE | 409 | already exists (incl. second response to a prescription request) |
| ALREADY_REVIEWED | 409 | medicine suggestion already approved or rejected |
| EMAIL_TAKEN | 409 | email already registered |
| PHARMACY_NOT_VERIFIED | 403 | pharmacy not verified |
| DEMO_DISABLED | 403 | demo accounts disabled |
| INSUFFICIENT_STOCK | 409 | not enough stock |
| ITEM_UNAVAILABLE | 409 | item no longer available |
| REQUEST_CLOSED | 400 | prescription request closed |
| IMAGE_PURGED | 410 | prescription image deleted by the retention job |
| NO_PHARMACIES_IN_SCOPE | 422 | no verified pharmacies in target scope |
| RESERVATION_STATE | 409 | reservation in wrong state |
| CONCURRENT_UPDATE | 409 | lock/optimistic-lock conflict, retry |
| DATA_CONFLICT | 409 | other integrity violation (still referenced) |
| INTERNAL_ERROR | 500/502 | unexpected or mail failure |
| ACCOUNT_SUSPENDED | 403 | account suspended by an admin (distinct from DEMO_DISABLED) |
| INVALID_PASSWORD | 400 | password confirming account deletion is wrong |
| ACCOUNT_ACTION_NOT_ALLOWED | 409 | delete/suspend refused (admin accounts) |
| OPEN_RESERVATIONS | 409 | pharmacy owner deleting account with CONFIRMED reservations |
| REQUEST_HAS_RESERVATIONS | 409 | prescription request has reservations; close it instead of deleting |
| RATE_LIMITED | 429 | too many auth attempts (login counts failed attempts only); `Retry-After` header gives seconds |
| PAYLOAD_TOO_LARGE | 413 | auth request body over 16 KB |

## Notifications

Notifications store a message key + params and are rendered in the request language when listed
(`GET /api/notifications`). Bundle keys are `notify.<event>.title` / `notify.<event>.body` with `{name}`
placeholders (`{pharmacy}`, `{items}`, `{customer}`, `{code}`, `{count}`, `{medicine}`, `{reason}`), identical across
languages. Full list: `README/READ_NOTIFICATION_MODULE.md` and `com.suwalink.event.NotificationKeys`.

## Frontend

The React app (`frontend/`) uses i18next with `frontend/src/locales/{en,si,ta}.json` (identical keys and
`{{placeholders}}`, enforced by `frontend/src/i18n/locales.test.ts`). The chosen language is persisted in
`localStorage` as `suwalink.lang` (default from `navigator.language`: `si`/`ta`, else `en`), sets `<html lang>`, and is
sent as `Accept-Language`. API errors are shown via `errors.<CODE>` (every code in the table above, plus the
frontend-only `NETWORK_ERROR` and `UNKNOWN`); the test parses that table, so a new backend code fails the
frontend tests until it is translated. Districts use `districts.<ENUM>`.

Sinhala and Tamil UI text was written by the implementer (not a native speaker) and is **pending native-speaker
review**, including all `errors.*`, `validation.*`, `districts.*` and the `common`, `nav`, `auth`, `register`,
`pharmacyRegister`, `theme` and `legal` namespaces.
This includes the sign-in, sign-up and password-reset screens (`auth.*`, `register.*`), the server field-error texts
`validation.NotBlank`, `validation.NotNull`, `validation.Email`, `validation.Size`, `validation.AssertTrue` (keyed by the
constraint name in `errors[].code`), and the placeholder Privacy Policy and Terms of Use (`legal.privacyDoc.*`,
`legal.termsDoc.*`), which are themselves drafts pending review (spec §13).
This also covers the pharmacy registration wizard and map picker: the new `pharmacyRegister.*` keys (`subtitle`, `stepOf`,
`progress`, `steps.*`, `intro.*`, `phoneHint`, `city`, `openingHours`, `openingHoursHint`, `coordinatesHint`,
`draftRestored`, `licenceTaken`, `edit`, `editSection`, `openingHoursNone`, `viewOnMap`, `submitting`, `failed`,
`successTitle`, `successBody`, `backHome`), `map.*`, `common.chooseDistrict`, `validation.tooLong` and
`validation.number`. Sinhala uses both ඖෂධ සැපයුම්හල and ෆාමසිය for "pharmacy", as earlier screens already did; a native
reviewer should pick one.
The home and search screens add `home.*`, `search.*`, `medicine.*` and `reservations.status.*`, also pending review.
The medicine, pharmacy and saved pages add `cart.*`, `pharmacy.*`, `saved.*`, `nav.saved` and more `medicine.*` and
`search.*` keys, also pending review. The cart and checkout add more `cart.*` keys and `nav.cart`. Prescriptions add `prescriptions.*`, and reservations add more `reservations.*` keys; settings add `settings.*` and `nav.settings`; all pending review.
The Phase 2B fix wave adds `prescriptions.replyCount_*`, `prescriptions.choosePhoto`, `prescriptions.noPhoto`,
`prescriptions.addedSome_*`, `reservations.all` and `reservations.loadError`, also pending review. The final fix wave adds
`cart.replaced`, also pending review.
Phase 2C's pharmacy section adds `pharmacyOwner.*` (`sectionLabel`, `nav.*`, `status.*`, `overview.*`, `settings.*`),
also pending review; Sinhala uses ෆාමසිය there.
Counts use i18next plurals (`_one` / `_other`); Sinhala keeps the same wording for both.

## Emails

Notification emails (sent after the creating transaction commits, on the `mail-` executor) and the password-reset
OTP email are rendered in the recipient's `preferredLanguage` from `email.*` and `notify.*` keys; Sinhala/Tamil text
is pending native-speaker review. Links use `app.frontend.base-url` (`FRONTEND_BASE_URL`). Demo users are mailed only at
`app.mail.demo-redirect` (`DEMO_MAIL_REDIRECT`), otherwise not at all. Placeholder names must match across the three bundles
(enforced by `MessageBundlesTest`).
